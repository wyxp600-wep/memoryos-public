01 / 为什么需要它

解释过的背景，
不必总从头整理。

昨天解决过的故障，下次仍要翻聊天记录；换了一位 AI，又要交代一遍项目。MemoryOS 把散落的信息变成能检索、能更新、能交接的工作资料。

Agent 就是能使用工具执行任务的 AI 助手，MCP 是它访问 MemoryOS 的接口。你继续使用已有的 AI 工具，让接入的助手查询共同的记忆库；人则通过工作台管理这些资料与任务。

02 / 核心功能

从记住背景，
到接续完整的工作。

除了保存记忆，还包括任务交接、知识整理、笔记关联和工具管理。每一项都围绕同一个目的：让积累的工作资料真正用得起来。

01 / 共享记忆

让不同 AI 接着同一个项目工作

把项目背景、个人偏好、技术决策和踩坑经验保存到本地。接入同一记忆库的 Agent，可以通过 MCP 读取共同背景；按项目组织内容，减少不同工作的相互干扰。

例如：在一个客户端确认的接口约定，换到另一个客户端后仍可查回，不必再次从头解释。

02 / 检索与依据

找到结论，也能查清为什么

按问题检索相关记忆，再打开完整正文。当前实现结合关键词与向量检索，并支持附加原文证据和记录引用，方便回到当时的依据核实。

例如：查“这个接口为什么要重试”，不只看到处理办法，还能回查适用条件、原文引用和验证记录。

03 / 工作检查点

长任务中断后，留下明确的接续位置

长期经验与临时进度分开保存。工作记忆可记录当前目标、已完成事项、阻碍和下一步；关联任务的结构化检查点可跨新会话继续读取。

例如：排查到一半换会话，下一位能先看“已经排除什么、还有什么没验证”，减少重复尝试。

04 / 任务协作

把分工、依赖和验收放到同一张看板

任务可以分派、认领、续租、标记阻塞、交回和完成；用依赖关系表达先后顺序。配置验收门的任务，完成前先检查验收条件。

例如：一位 Agent 修改接口，另一位在前置任务完成后补测试；交接时保留任务状态与证据。

05 / 知识采集

让已有资料成为可检索的经验

从支持的本机明文来源读取记忆、规则和对话资料，进行去重检查；需要提炼的内容可交给配置好的 LLM 整理后入库。来源范围和提炼服务需要配置。

例如：把过去排查故障的长记录，整理成“什么情况下、采取什么行动、依据是什么”的经验条目。

06 / 记忆治理

让过时经验能够纠正，而不是一直被沿用

查看可能冲突的新旧结论、重复候选、待归档内容和使用情况。通过反馈标记有误或过时的记忆，保留追溯线索；疑似冲突需要核实处理。

例如：部署方式变了，可以标记旧方案已被替代，并保留当时为何采用它的记录。

07 / 笔记与图谱

把笔记、记忆和任务联系起来

支持 Obsidian 笔记库的增量导入、记忆导出，以及笔记内容和反向链接浏览；统一图谱把笔记、记忆与任务卡的关联放到一起查看。

例如：从一份项目笔记找到相关技术决策，再追到处理这项问题的任务卡。

08 / 方法复用

把零散经验整理成可审查的操作方法

从已有记忆生成候选方法包，保留来源和适用条件，支持执行前预检及结果反馈。方法库的运行操作限于服务端允许的只读检查，生成文字不会直接变成执行授权。

例如：把多次连接排查的经验，整理成先检查配置、再验证连接、最后核对读写的排查步骤。

09 / 技能同步

一处维护技能，分发到支持的工具

用中央技能目录管理 SKILL.md，向支持的客户端目录同步。相同内容跳过，发生替换时先备份；实际目标由本机配置和客户端能力决定。

例如：更新一份代码审查技能后，同步到 Codex、Claude Code 等已配置目标，减少手工复制。

10 / 智能体工作台

在同一界面查看对话、步骤和结果

内置智能体对话和运行记录界面，可接入兼容的 LLM 服务，查看工具调用与输出。命令执行受权限和审批配置约束；需要你自行配置模型服务。

例如：围绕某项任务提问，查看它检索了哪些资料、调用了哪些工具，以及哪些操作还在等待批准。

11 / 连接与管理

让人能看懂系统现在处于什么状态

通过可视化界面管理记忆、任务、笔记、工具连接和治理信息，检查连接反馈、读写活动、运行健康及审计记录。不同客户端的连接检测覆盖范围可能不同。

例如：分清“客户端已配置”“实际连接成功”和“已经发生记忆读写”，排查接入问题更有依据。

03 / 特点与优势

让资料有来处，
让接力有下一步。

把存储、检索、检查点和治理连起来。实际价值来自这些机制如何服务日常工作，而不只是多存几段聊天。

特点实现基础对使用者的价值
跨工具延续通过 MCP 接入共同记忆库更换支持 MCP 的客户端时，可以继续查询已有背景与进展。
经验与进度分开长期知识加任务检查点既保留可复用判断，也交代眼下做到哪里，减少交接信息混杂。
结果可回查正文、证据、引用和审计记录遇到重要结论时，能够追到依据，方便核验和纠错。
持续整理冲突检查、失效反馈和归档机制让记忆库有修正与维护入口，减少旧结论被反复沿用的风险。
本地掌握数据SQLite 本地持久化，提供导出与笔记同步可以在自己的设备上保存和管理知识；外部服务调用另由配置决定。
人和 Agent 共用工具接口加可视化工作台Agent 能调用工具，人能查看、管理和追踪同一份工作资料。

实际收益取决于资料质量、客户端调用方式与配置；不承诺自动消除重复工作或保证 AI 判断正确。

07 / 使用前了解

知道它能做什么，
也知道怎样用得可靠。

接入以后，所有 AI 会自动同步聊天吗？

不会。客户端需要配置到同一个记忆库，并调用检索、写入或任务工具。MemoryOS 提供共同资料和协作机制；Agent 是否按约定读写，取决于客户端、规则和权限配置。

数据在本地，是否意味着完全离线？

记忆数据库保存在本机。外部 LLM、嵌入服务及模型下载按配置访问网络；使用外部服务时，相应请求内容会发给服务提供方。

内置模型负责什么？

BGE-M3 是集成的第三方嵌入模型，用来辅助匹配相近意思，不是我们训练的聊天模型。共享记忆本身不要求内置模型，但当前桌面实现启用了本地嵌入。采集提炼和内置智能体还需要配置相应 LLM 服务。

保存过的经验、生成的方法能直接照做吗？

需要核实适用条件和原始依据。保存、引用或生成候选方法都不等于事实已验证；任务分派也不保证客户端会启动执行。写入、命令执行与部分管理动作受权限和审批配置约束。

笔记、技能和采集功能需要哪些准备？

笔记同步需指定本机笔记库，技能同步需配置支持的目标目录，资料采集需可读来源；涉及智能提炼时还需可用 LLM 服务。各客户端的检测、技能目录和自动化能力并不完全相同。
